# 菜谱向量化与检索 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让已发布菜谱按方案一次向量化写入真实 Milvus，并按字段过滤（必要时再向量）检索到正确菜号，再交给主料门槛。

**Architecture:** `platform-vector` 增加「无查询向量、仅 filter」的标量查询；营养服务修写入（预计算向量、只写已发布、种子不写空标量），并接线 `RecipeIntent` → `RecipeVectorFilter` → Milvus。真库冒烟连 `154.8.23.238:19530`。

**Tech Stack:** Java 21、Spring Boot 4.1.1、Milvus Java SDK、百炼 `qwen3-vl-embedding`、JUnit 5、Maven

## Global Constraints

- 集合名固定 `recipe_chunk`；向量 1024 维；模型 `qwen3-vl-embedding`
- 一行一道菜，不按字切分
- 字段过滤不靠相似度；有点名/病情时失败不得退回全库
- 主料门槛与规则分仍在业务层，公共包只返回主键
- 密钥只写本地 `application-local.yml`，不入库
- 本轮不做全量对账台、下架删向量后台、`platform-model` 迁移

**Interfaces:**
- `matchIds(..., String text, List<String> conditions)`
- `narrow` 逻辑：

```text
intent = RecipeIntent.parse(text, conditions)
filter = RecipeVectorFilter.expr(intent.cuisine(), intent.kind(), intent.preferTags(), intent.conditions())
hasFilter = filter 非空

if (!hasFilter && !intent.fuzzy()) return dishes   // 全量主料

if (hasFilter && !intent.fuzzy())
  ids = vectors.query(filter, 30)
  if vectors 失败或空 → return List.of()           // 不退回全库
  return HybridRecall.pool(dishes, ids)

if (intent.fuzzy())
  queryVec = embedding.embed(intent.fuzzyText())
  byWord = HybridRecall.recall(intent.fuzzyText(), stored, null)
  byVector = vectors.search(queryVec, filter, 30)  // filter 可空
  if hasFilter && byVector.isEmpty() && byWord 滤后为空 → return List.of()
  merged = ...
  return HybridRecall.pool(dishes, merged)
```

注意：有 filter 时，`HybridRecall.pool` 在空交集返回空；无 filter 且向量失败时可按现逻辑退回 `dishes`。
