# 长短期记忆企业级闭环设计 V2.1（持久化权威）

状态：**工程补充基线**  
继承：`2026-11-17-长短期记忆企业级闭环-design-V2.md`  
原则：**不以 JVM 为权威**；不上 MQ/Outbox；同步 DB 事务。

---

## 0. 决定表

| 项 | 决定 |
| --- | --- |
| 偏好权威 | MySQL `diet_preference_*` |
| 会话权威 | Redis `nutrition:session:{id}` + `preferenceEpoch` |
| JVM | 仅 L1；可丢，必须可从权威重建 |
| 过敏嫌疑 | MySQL `diet_allergy_suspect`；升临床仅显式确认 API |
| 客户端字段 | `source=client`，忌口强度 ≤ MODERATE，不得作 ABSOLUTE 硬过滤 |
| 写入 | 同步事务；失败则 `committed=false`，不改 L1 |

---

## 1. 权威分层

```text
MySQL 偏好事实/事件/审核  ──权威──► PreferenceStore L1（可丢）
MySQL 过敏嫌疑           ──权威──► AllergySuspectStore（读穿）
Redis 会话快照           ──权威──► SessionMemoryStore L1
进程内 MemoryMetrics     ──非业务── 可丢
```

---

## 2. 写入契约（writeBarrier）

1. 校验通过后 **先** MySQL 事务：关旧 + 插新事实 + 插事件 + epoch。  
2. 成功才替换 L1，并 `committed=true`。  
3. 失败：L1 不变，`committed=false`；编排器不刷新长期、不 auto-replace。  
4. `eventId` 幂等以 **DB** `diet_memory_event` 为准。  
5. `expireDue` 在 DB 关到期 TURN/TEMPORARY，再 `invalidate` L1。

单测无 Mapper：允许无参 `PreferenceStore()` 纯内存；生产注入路径 Mapper 不可用则 commit 失败。

---

## 3. 会话

- 有 Redis：`getOrCreate` **先读 Redis**；无 key 才建本地并回写。  
- `save` 必须写 Redis；失败记日志，靠下回合读穿恢复。  
- 无 Redis（单测）才纯 JVM。

---

## 4. 过敏嫌疑

- 表 `diet_allergy_suspect`：pending 状态。  
- `dismiss`：pending=false。  
- `confirm`：pending=false，且 owner 为患者时调用临床 `addAllergy(..., confirmed=true)`。

---

## 5. 治理与隐私

- retract / correct：DB 成功后可选 `sessionId` 重载 longTerm + 绝对忌口换菜重校验。  
- `DELETE` 偏好：对现行口味批量 RETRACT + review DELETE。  
- 客户端 `avoidFoods` merge：强度 MODERATE，evidence=`client`。

---

## 6. 分期

| 期 | 内容 |
| --- | --- |
| E1 | DB-first PreferenceStore + expireDue DB + Redis-first Session |
| E2 | 过敏嫌疑表 + confirm/dismiss API |
| E3 | writeBarrier 编排、client 降权、治理重校验、隐私删除、契约测 |
