# 时效偏好记忆设计（企业级）

状态：施工。小改动落在记忆层；主编排不变大。

## 1. 原则

- 「不吃海带」= **负向饮食偏好**（`AVOID`），不是临床过敏。
- 「喜欢/最喜欢海带」= **正向偏好**（`LIKE`）。
- **同一主体同一时刻只允许一条现行事实**；新陈述使旧陈述 `validTo = now`（过期），新陈述 `validFrom = now, validTo = null`（现行）。
- 配餐/过滤**只读现行**（`validTo == null`），历史保留供审计，不参与推荐。

## 2. 时间线例子

| 时间 | 用户说 | 现行结果 |
| --- | --- | --- |
| T1 | 我不喜欢吃海带 | 现行 AVOID(海带) → 推荐不含海带 |
| T2 | 我现在喜欢吃海带了 | AVOID 过期；现行 LIKE(海带) → 可出现海带 |
| T3 | 以后又不喜欢了 / 我不喜欢海带 | LIKE 过期；现行 AVOID(海带) → 不能有海带 |

判定口诀：**现在用现行，过去的已过期不再生效。**

## 3. 旁路抽取（不大改主 Agent）

```text
用户原文
  → MemoryExtractor（旁路，只看用户话）
  → PreferenceEvent[]（kind + subject + confidence）
  → TemporalPreferenceStore.apply（关旧开新）
  → 刷新 LongTermMemory 快照中的 avoidFoods / preferLikes
主路径 IntentUnderstander 仍只管推荐任务
```

- 抽到「过敏」语气 → **不**写入 AVOID 偏好升硬；走过敏确认流（本轮可只记候选 + needsConfirm）。
- 高置信偏好可直接 apply；低置信可回显「已记住：不吃海带」。

## 4. 存储

进程内按 `patientId`（无则 `session:`）存事实链；后续落库字段：`subject, polarity, valid_from, valid_to, source_turn`。
