# 时效饮食偏好完整方案

状态：待确认后施工。  
依据：慢病/减重食材推荐、对话规划、记忆分层；场景「海带不喜欢/又喜欢」「以前/现在不喜欢吃什么」。  
约束：不大改主推荐编排；克数与主料仍由 Java；不上 Graph 接管；临床硬约束与口语偏好分离。

---

## 1. 目标

1. 从用户话抽取**结构化饮食偏好**（非聊天原文）。  
2. **时效**：新陈述使旧陈述过期；**推荐只看现行**。  
3. **可问答**：能答「以前 / 现在」×「不喜欢 / 喜欢」吃什么。  
4. **旁路**：记忆抽取与问答不塞进克数/主料主 Agent。  
5. 与过敏、病情、缺料、当次口味、多患者等场景边界清晰、可审计。

---

## 2. 核心场景矩阵（你的例子）

### 2.1 写入

| # | 用户说 | 记成 | 禁止记成 |
| --- | --- | --- | --- |
| A | 我不喜欢/不吃海带，帮我推荐菜 | 现行 `AVOID(海带)` + 可同时 RECOMMEND | 过敏；家里有海带 |
| B | 我最喜欢娃娃菜 | 现行 `LIKE(娃娃菜)` | 强制上含娃娃菜的菜 |
| C | 我现在喜欢吃海带了 | 过期 AVOID，现行 LIKE | AVOID+LIKE 同时现行 |
| D | （C 之后）又不喜欢海带了 | 过期 LIKE，现行 AVOID | 仍按 C 喜欢过滤 |

### 2.2 问答

| # | 问 | 读 | 一直不喜欢海带时 | T1 AVOID→T2 LIKE 后 |
| --- | --- | --- | --- | --- |
| Q1 | 现在不喜欢吃什么 | **现行** AVOID | 海带 | 无海带 |
| Q2 | 以前不喜欢吃什么 | **历史上出现过** AVOID（含仍现行） | 海带 | 海带 |
| Q3/Q4 | 现在/以前喜欢吃什么 | 现行 / 历史 LIKE | 按事实 | 按事实 |

口诀：**现在 = 现行；以前 = 曾经有过；推荐 = 只用现行。**

### 2.3 推荐

| 现行 | 行为 |
| --- | --- |
| AVOID | 偏好过滤（字段独立于 allergen） |
| LIKE | 软 hints，不强制 |
| allergen | 硬拦截；口语「不吃」不升过敏 |

## 3. 领域模型与时效

```text
PreferenceFact
  ownerId, subject, polarity(AVOID|LIKE|CUISINE|TAG)
  validFrom, validTo(null=现行)
  source, utteranceRef, strength(ABSOLUTE|SOFT)  // 见 §5.2
```

- 同 owner+subject 上 AVOID↔LIKE **互斥**；写入时旧现行 `validTo=now`。  
- `current(now)` / `pastAvoids` / `pastLikes` / `at(t)` 投影见前版；默认「以前」= 历史上出现过该 polarity 的 subject。

---

## 4. 架构（旁路）

```text
用户原文
  ├─ MemoryExtractor（旁路）→ events / queries / allergySuspects / turnOnlyHints
  │         ↓ apply
  │    PreferenceStore（事实链）
  │         ↓
  │    刷新 longTerm 现行投影 │ QUERY 答句 │ 推荐过滤
  └─ IntentUnderstander → Planner → Executor（推荐/换菜…）
```

主路径不负责偏好词典抽取。`QUERY_MEMORY` 可由旁路 `queries` 直接驱动，或主理解产出同构任务。

## 5. 基于本产品必须一并设计的注意点

### 5.1 语义分层（最容易混）

| 说法 | 层 | 强度 |
| --- | --- | --- |
| 虾过敏 / 医生说不能碰 | 临床 allergen | 硬；须确认/档案 |
| 我不吃/不喜欢海带 | 偏好 AVOID | 默认偏好过滤（见 5.2） |
| 今天别放香菜 / 这顿清淡 | **短期** turnHints / 本轮 missing 式 | 不升长期 |
| 家里没有可乐 | 会话 `missing` | 缺货，不是偏好 |
| 把鸡蛋换成鸭蛋 | SUBSTITUTE 流程 | 不写偏好，除非用户说「以后都不要鸡蛋」 |

**「没有」≠「不喜欢」**：没有可乐 → missing；不喜欢可乐 → AVOID。

### 5.2 「不吃」强度：绝对 vs 软

口语模糊。默认：

- 「不吃 / 不要 / 别给我」→ `AVOID` + `strength=ABSOLUTE` → **过滤**（与现推荐体验一致）  
- 「不太爱 / 少吃点」→ `AVOID` + `strength=SOFT` → **降权不删**（第一版可先全部按 ABSOLUTE，SOFT 预留）  
- 「过敏」→ 绝不走 AVOID 升硬，走 `allergySuspects` + 确认  

第一版可只实现 ABSOLUTE；字段预留 strength。

### 5.3 与病情 / 安全硬约束冲突

优先级固定（不可被偏好推翻）：

```text
测量禁配餐 STOP
  > 过敏 / 绝对临床禁忌
  > 病情适合·不适合（控糖等）
  > 主料门槛 / 已发布菜
  > 现行 AVOID（偏好）
  > LIKE / 菜系 / 标签软偏好
```

例：用户 LIKE 高糖零食，但控糖不适合 → **不上该菜**；可说明「按控糖限制未推荐」。  
AVOID 与病情一致时静默兼容；冲突时硬约束胜出并简短解释。

### 5.4 一句多意图

「我不吃海带，清淡一点，再推荐三道菜」：

1. 旁路：`AVOID(海带)`  
2. 「清淡一点」→ **短期** fuzzy/hint，不写长期 TAG（除非说「以后都要清淡」）  
3. 主路径：RECOMMEND（带现行 AVOID + 当次 hint）  

「以前不喜欢吃什么，顺便再推荐」：先答记忆，再推荐（同回合有序）。

### 5.5 一句自相矛盾

「我不吃海带但我现在又想吃海带了」：  
按**时间顺序/转折**取最后有效事件（旁路输出有序 events，后者覆盖前者）。  
无法消解 → 不写入，回问一句。

### 5.6 主体归一

- 海带/干海带/昆布：归一到标准食材名或 foodId（走现有 normalize/别名）  
- 写事实用 **canonical subject**；问答展示用规范中文名  
- 错别字：高置信自动；低置信确认后再 apply（与食材分档一致）

### 5.7 LIKE 食材 vs 菜系 vs 标签

| 主体类型 | polarity | 例子 |
| --- | --- | --- |
| 食材 | LIKE / AVOID | 海带、娃娃菜 |
| 菜系 | CUISINE | 川菜（同一时刻一条现行菜系或允许多条：产品定；默认可多选现行） |
| 标签 | TAG | 减肥、快手 |

「最喜欢娃娃菜」≠「只做川菜」。CUISINE 是否互斥：默认**可并存多条现行菜系**；若说「以后只吃粤菜」则关其他 CUISINE。

### 5.8 家庭库存 / 患者归属

- owner = `patientId`；未登录 = `session:{id}`  
- 登录后：**合并** session 事实链到 patient（同 subject 以时间较新的为准关旧开新）  
- 多患者账号：禁止串记忆；每次请求必须带对的 patientId  

### 5.9 会话短期 vs 长期刷新

偏好 `apply` 成功后：

- **立即**刷新本会话 `longTerm` 现行投影（不要等下次会话）  
- 否则「刚说不吃海带又推荐海带」  

当次「这顿不要香菜」只进短期，**不** apply 长期。

### 5.10 与换菜 / 加菜 / 缺料

- 已上桌的三道里若含新 AVOID：增量 **只换掉违规那几道**，其余保留（符合「不整表重刷」）  
- 新 AVOID 与 missing 同时存在：并集过滤  
- 加菜：新菜也不得命中现行 AVOID/过敏  

### 5.11 代替（SUBSTITUTE）

- 「可以用海带代替紫菜吗」：先病情适合检查；再看现行 AVOID(海带)→ 直接不建议代替  
- 代替成功**不**自动 LIKE；用户说「以后都用海带」才写 LIKE  

### 5.12 测量禁配餐 / Kill Switch

`measurementStopsPlanning`：可问答记忆，**不可**推荐；apply 偏好仍允许（用户可先改口味档案）。

### 5.13 隐私与审计

- 存结构化事实，不存完整病历闲聊  
- history 默认不对 C 端全量下发；答「以前」只返回 subject 列表  
- 每条事实保留 source + 时间，供客服/合规追问「何时说过不喜欢」

### 5.14 时钟与并发

- 服务端 `Instant.now()` 为唯一时间源  
- 同用户连续请求串行化 apply（按 owner 锁或 DB 乐观锁），避免两句乱序把时效打乱  

### 5.15 抽取失败与兜底

- 模型失败：不写偏好；推荐仍可用已有现行记忆  
- 禁止规则主路径猜「不吃」；无模型时宁可不抽  

### 5.16 未成年人 / 代理说话

「我孩子不吃海带」：第一版要求绑定正确 patient（孩子档案）；无法区分则 **不写入** 当前成人档案，提示切换档案。

### 5.17 医嘱忌口 vs 口味

专业目标/医嘱忌口若已在临床或专业目标中：优先临床；口语偏好不能放宽医嘱。

## 6. 旁路抽取契约

```json
{
  "events": [
    { "polarity": "AVOID", "subject": "海带", "strength": "ABSOLUTE", "confidence": 0.92 }
  ],
  "queries": [
    { "tense": "CURRENT", "polarity": "AVOID" }
  ],
  "turnOnlyHints": ["清淡"],
  "allergySuspects": [],
  "needsDisambiguation": null
}
```

- events 有序；后覆盖前（同 subject）  
- queries 触发固定模板问答  
- turnOnlyHints 不入 PreferenceStore  
- allergySuspects 只提示确认  

写入：`confidence≥0.85` 直接 apply；过敏嫌疑必须确认。

## 7. 问答与推荐执行

**问答模板（可审计）**

- 现在不喜欢：`目前记录您不喜欢：海带、…` / `目前没有记录不喜欢的食材。`  
- 以前不喜欢：`您曾经不喜欢：海带、…`  
- 列表仅来自 Store 投影，模型不得编造。

**推荐**

- 过滤：现行 ABSOLUTE AVOID ∪ allergen ∪ missing ∪ 病情硬过滤  
- Hints：现行 LIKE + CUISINE + TAG + turnOnlyHints  
- 过期事实不过滤

## 9. 端到端故事（验收脚本）

```text
T1 不喜欢海带 + 推荐     → AVOID 现行；菜无海带
T2 以前不喜欢吃什么     → 海带
T3 现在不喜欢吃什么     → 海带
T4 现在喜欢海带了       → LIKE 现行；其后可含海带
T5 以前不喜欢 / 现在不喜欢 → 海带 / 无海带
T6 又不喜欢海带了       → AVOID；推荐再无海带；以前&现在均可答海带
T7 虾过敏               → 不进 AVOID；过敏确认流
T8 这顿清淡一点         → 仅短期 hint
T9 家里没有可乐         → missing，不是 AVOID
```

## 12. 确认点（产品拍板）

1. 「以前不喜欢」= 历史上出现过的 AVOID（推荐默认）还是「仅已过期」？ → **默认前者**（一直不喜欢时以前/现在都能答海带）。  
2. 第一版 AVOID 是否全部按过滤（ABSOLUTE）？ → **是**。  
3. 多菜系现行是否允许多选？ → **允许**；「只吃 X」再关其他。
