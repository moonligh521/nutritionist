# 复杂提问 · 第一轮语义理解完整方案

状态：**U0 已落地；金标 1000 oracle+live 达标（2026-11-18）**  
日期：2026-11-18  
场景唯一目标：**用户一次开口（一句或一段复杂话），同步链路只打 1 次文本模型，精准识别出全部业务意图、槽位与本轮约束。**

本方案是该场景的**唯一施工依据**。  
总纲中的 Planner 冲突消解、召回降级、记忆运营等，**不在本场景范围**；仅保留理解输出之后的最小衔接（合法化、指代补全、歧义则本回合澄清）。

继承（只读边界，不扩 scope）：

- 任务白名单：`TaskType`（GREETING / OUT_OF_SCOPE / RECOMMEND / REPLACE_ONE / ADD_KIND / MISSING / SUBSTITUTE / CONFIRM_FOODS）
- 问餐同步 / 记忆异步：`2026-11-18-问餐同步与记忆异步拆分-design.md`
- 前序专项：`2026-11-18-第一轮语义理解精准识别-design.md`（本文为其完整版，冲突以本文为准）

## 0. 场景定义

### 0.1 一句话

> 用户对着「问餐/营养选菜」说了一段**可能很绕、很长、多意图混杂**的话；系统必须在**第一轮同步理解**里把它拆对，而不是靠多轮猜或后端瞎执行。

### 0.2 场景内 / 场景外

| 场景内（必须做好） | 场景外（本方案不做） |
| --- | --- |
| 多意图拆分与排序 | 荐哪几道菜、主料是否齐全 |
| 换菜/加汤/缺料/代替槽位 | 向量召回、降级阶梯 |
| 本轮忌口/菜系/清淡等约束 | 记忆 LLM 异步落库细节 |
| 指代（第二个/这个/换一个） | 空结果运营文案体系 |
| 歧义时澄清，不硬猜 | 通用闲聊、改克数、编菜 |
| 理解金标与真模型达标 | 微调平台（仅预留 U-P3） |

### 0.3 默认产品决定（本方案拍板）

1. **同步只 1 次**理解模型；不做疑难二次调用。  
2. **歧义**（`ambiguities` 非空或关键槽位 confidence&lt;0.55）：本回合**只澄清、不找菜**。  
3. 验收门槛：Task-set Exact ≥92%；Slot Exact ≥90%；Constraint F1 ≥88%；换菜/加汤/绝对忌口漏检 ≤2%；假 OUT_OF_SCOPE ≤1%。

## 1. 用户场景目录（设计锚点）

每个场景都有「输入形态 → 期望理解结果」。实现与金标必须覆盖。

### S1 单意图基线

| ID | 用户说 | 期望 |
| --- | --- | --- |
| S1.1 | 你好 | `[GREETING]` |
| S1.2 | 今天天气怎么样 | `[OUT_OF_SCOPE(天气)]` |
| S1.3 | 家里有番茄鸡蛋，推荐一下 | `[RECOMMEND(番茄,鸡蛋)]` |
| S1.4 | 水煮蛋换一个（已荐含该菜） | `[REPLACE_ONE(水煮蛋)]` |
| S1.5 | 再加个汤 | `[ADD_KIND(汤)]` |

### S2 复合多意图（核心痛点）

| ID | 用户说 | 期望 |
| --- | --- | --- |
| S2.1 | 不吃香菜，用番茄鸡蛋推两道 | constraints.avoid+=香菜 + `[RECOMMEND]` |
| S2.2 | 水煮蛋换一个，再加个汤 | `[REPLACE_ONE][ADD_KIND(汤)]` 两条都在 |
| S2.3 | 想吃川菜清淡点，家里有豆腐青椒 | RECOMMEND + cuisine=川菜 + tags/hints含清淡 |
| S2.4 | 绝对不能吃虾，帮我推荐 | absoluteAvoid+=虾 + RECOMMEND |
| S2.5 | 没有土豆了，用西红柿代替 | `[MISSING(土豆)]` 与/或 `[SUBSTITUTE]` 按语义；不得吞成单 RECOMMEND |
| S2.6 | 香菜别放，第二个换掉，再来个汤 | avoid + REPLACE(第2道) + ADD_KIND |

### S3 指代与省略

| ID | 上下文 | 用户说 | 期望 |
| --- | --- | --- | --- |
| S3.1 | 菜=[水煮蛋,番茄炒蛋] | 换第二个 | REPLACE dishHint=番茄炒蛋 或 dishIndex=2 |
| S3.2 | 焦点=水煮蛋 | 那个换掉 | REPLACE → 水煮蛋 |
| S3.3 | 仅一道菜 | 换一个 | REPLACE → 该道 |
| S3.4 | 两道菜、无焦点 | 换一个 | ambiguities 问换哪道；或 confidence 低 |

### S4 约束分级

| ID | 用户说 | 期望 |
| --- | --- | --- |
| S4.1 | 不太喜欢香菜 | avoidFoods，非 absolute |
| S4.2 | 绝对不能吃海鲜 | absoluteAvoidFoods |
| S4.3 | 历史已有忌口海带，用户只说推荐 | 不把海带再抄进 turnConstraints |

### S5 易错负例

| ID | 用户说 | 禁止 |
| --- | --- | --- |
| S5.1 | 换一个 / 加个汤 | 禁止 OUT_OF_SCOPE |
| S5.2 | 再加个汤 | 禁止当成全新 RECOMMEND 清掉已有菜的意图 |
| S5.3 | 北京天气，顺便推荐下 | OUT_OF_SCOPE 可与业务并存时：应出业务 task，域外可旁支；**不得只有域外而丢荐菜**（若同句确有荐菜意图） |

### S6 低置信澄清

| ID | 情况 | 期望 |
| --- | --- | --- |
| S6.1 | 「换那个」且两道都可能 | ambiguities，本回合不执行 REPLACE |
| S6.2 | 菜名口误对不上已荐 | ambiguities 选项=已荐菜，不硬匹配 |

## 3. 模块设计

### 3.1 ContextPacker

**输出结构（逻辑模型）：**

```text
ContextPack {
  utterance: string
  requestFoods: string[]
  currentDishes: { index: int /*1-based*/, id, name }[]
  lastFocusedDishId / name: optional
  phase: string          // 无则 IDLE
  preference: {
    avoid, absoluteAvoid, cuisines, tags, conditions, allergens  // 各 ≤5，空="无"
  }
  domain: "nutrition_ask_meal"
}
```

规则：

- `currentDishes` 顺序 = 会话当前展示顺序（与「第几个」一致）。  
- 偏好只摘要，**禁止**全量 tasteItems 倾倒。  
- Pack 失败（无会话）仍可理解，菜列表为空。

### 3.2 FewShotPicker

- 金标分桶：`multi_intent|anaphora|replace|add_kind|constraint|oos|missing|clarify`  
- 选择：根据 utterance 关键词 + 是否有 currentDishes + 是否像复合句，取 **4～8** 条  
- 注入 prompt 的格式统一：`【例】用户=… 菜=… → JSON=…`  
- 代码内 **不再**写死超过 4 条静态样例作唯一来源；静态仅作冷启动保底

### 3.3 UnderstandLLM（Prompt 合同）

五段固定：

1. 角色与禁止（不荐菜名、不改克数、不编病情）  
2. **原子拆分法** + 决策树（业务在前，OUT_OF_SCOPE 最后）  
3. 类型–槽位硬表（含 dishIndex、confidence）  
4. 动态 few-shot + 固定负例 4 条  
5. ContextPack 序列化 +「只输出 JSON」

系统说明中的原子规则（必须原样约束模型）：

- 忌口/菜系/清淡 → **优先** `turnConstraints`，不是假 task  
- 「换…再加…」→ **两条 task**，禁止合并  
- 选菜相关 **禁止**单独 OUT_OF_SCOPE  
- 绝对不能吃 → `absoluteAvoidFoods`；不太喜欢 → `avoidFoods`  
- 拿不准指代 → `ambiguities`，不要瞎填 dishHint  

温度：0～0.2。超时/失败：薄兜底（有 foods→RECOMMEND；短问候→GREETING；否则请用户用选菜话重说——**标注 `understand.degraded=true`**，尽量少用假 OOS）。

### 3.4 TurnIntentV2 契约

```json
{
  "tasks": [
    {
      "type": "REPLACE_ONE|ADD_KIND|RECOMMEND|…",
      "rawFoods": [],
      "dishHint": "",
      "dishIndex": null,
      "kind": "",
      "missingFood": "",
      "fromFood": "",
      "toFood": "",
      "topic": "",
      "confidence": 0.0
    }
  ],
  "turnConstraints": {
    "avoidFoods": [],
    "absoluteAvoidFoods": [],
    "cuisine": "",
    "kind": "",
    "preferTags": [],
    "turnHints": []
  },
  "ambiguities": [
    { "code": "DISH_REF|FOOD_REF|KIND_REF", "options": [], "ask": "" }
  ]
}
```

兼容：旧解析无 confidence 时默认 0.8；无 ambiguities 当空数组。

### 3.5 IntentNormalizer

| 步骤 | 行为 |
| --- | --- |
| 枚举校验 | 非法 type 丢弃 |
| 槽位 | 空白串→空；RECOMMEND 可无 rawFoods（仅约束时） |
| 置信度 | &lt;0.55 的 REPLACE/ADD/SUBSTITUTE → 移入 ambiguities 或丢弃并打点 |
| 去重 | 同 type+主槽位相同合并 |
| 反抄袭 | constraints 中与 Snapshot 完全相同的项可保留本轮口头再声明；**禁止**把未在原文出现的历史忌口由模型「补进」——Normalizer 若检测到「原文未提且等于历史」则剥掉（可选开关，默认开） |
| 空 tasks | 走薄兜底 |

### 3.6b IntentSafetyNet（落地补充）

真模型抽检曾出现大量假 `OUT_OF_SCOPE`（换一个/再加汤/没有了/代替）。  
增加**高置信词法护栏**：仅当结果为空或唯一 task=OUT_OF_SCOPE 时，对上述固定句式纠偏；不开放域猜菜。  
与「模型主路径」并存：模型判对则护栏不触发。

### 3.6 SlotResolver

| 输入 | 输出 |
| --- | --- |
| dishIndex∈[1,n] | dishHint=currentDishes[i-1].name，写 lastFocused |
| 「这个/那个」+ lastFocused | dishHint=焦点菜 |
| REPLACE 且 dishHint 空且仅 1 道菜 | 自动该道 |
| REPLACE 且 dishHint 空且多道、无 index | 生成 DISH_REF ambiguity |
| dishHint 模糊唯一命中已荐 | 归一到标准名 |
| dishHint 命中 0 或 &gt;1 | ambiguity |

**禁止**：用开放域向量乱猜未在已荐列表中的菜名当 REPLACE 目标（除非原文明确写出菜名）。

### 3.7 澄清交接（场景内终点）

当 `ambiguities` 非空：

- `plan` 侧等价于确认门禁：不调用找菜  
- `explanation` 用 `ask` + `options` 模板拼接  
- 用户下一轮选择 → 走原有 confirmation / 或再理解（新一轮的「第一轮」）

## 4. 与现网编排衔接（最小）

`DialogueOrchestrator` 同步理解处改为：

```text
pack = ContextPacker.from(session, command)
intent = UnderstandFacade.interpret(pack)  // 内含 LLM+Normalize+Resolve
applyTurnConstraints(intent.constraints)
if intent.needsClarify():
    reply clarify; save; return
else:
    plan/execute  // 既有
```

记忆异步、规则同步忌口：**保持现状**，不在本方案改语义。
