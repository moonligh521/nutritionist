# 对话规划与增量推荐设计

状态：已确认，按本文件施工。  
依据：产品讨论（问候/拒答、多任务规划、长短期记忆、增量换菜/加汤、错别字分档）与 `docs/方案`。

## 1. 目标与非目标

### 目标

- 用户话术先经**模型语义理解**，再由 Java **规划并增量执行**。
- 支持：问候、职责外拒答、报食材推荐、换一道、加品类（如汤）、缺少食材换菜、代替；一句话多任务时同回合按序执行。
- **长期记忆 + 短期（会话）记忆**：病情等会话内带着走，不每轮重查。
- 错别字：**词表/别名为主**；高置信自动纠正并回显；低置信必须确认后才找菜。

### 非目标

- 模型改克数、编菜、从闲聊推断病情、放宽主料门槛。
- 通用多轮闲聊。
- 用 Spring AI / Graph 接管安全、求解与确认控制权。

## 2. 架构

```text
请求（sessionId、patientId、text、可选 foods/profile/clientDishes）
  → 装载记忆（长期 → 短期快照）
  → 语义理解（模型 → 任务 JSON）
  → 规划器（Java：白名单计划、排序、冲突消解）
  → 执行器（Java：增量执行，共享 WorkingMemory）
  → 写回短期记忆 + 响应
```

原则：模型只负责听懂；Java 决定能不能做、做哪一步、动哪几道菜。

## 3. 记忆

详见 `2026-11-17-对话记忆分层-design.md`。

| 层 | 内容 | 生命周期 |
| --- | --- | --- |
| 长期 | 病情、过敏、忌口、用药、测量禁配餐、稳定菜系/标签偏好 | 跨会话 |
| 短期 | 长期快照副本 + 当前菜/食材/缺料/纠正/当次 hints | 会话 |
| 工作记忆 | 本回合任务队列与中间结果 | 单请求 |

- 会话首次按 `patientId` 装载 `LongTermMemory`；同 version 不重查。
- 忌口与稳定偏好写入 `PatientTasteProfile`；当次「清淡一点」只进短期 hints。

## 4. 理解输出（模型）

理解层以模型为主：只输出枚举任务 + 槽位。禁止用正则主路径猜换菜/加汤/代替/食材列表。  
无模型或 JSON 非法时的极薄兜底：请求里已有 `foods` → `RECOMMEND`；短问候词 → `GREETING`；其余 → `OUT_OF_SCOPE`（请用业务话重说）。

模型输出例如：

- `GREETING`
- `OUT_OF_SCOPE`（topic）
- `RECOMMEND`（rawFoods / foods / textHints）
- `REPLACE_ONE`（dishHint）
- `ADD_KIND`（kind）
- `MISSING`（food）
- `SUBSTITUTE`（from、to、recipeHint）
- `CONFIRM_FOODS`（由规划器在低置信时插入，模型不直接发明）

非法 type → 理解失败，引导重说，不进推荐链。

## 5. 计划与冲突

| 计划 | 行为 |
| --- | --- |
| GREETING | 固定身份文案 |
| OUT_OF_SCOPE | 拒答 + 职责 |
| CONFIRM_FOODS | 阻断后续找菜，只返回候选 |
| RECOMMEND | 归一→过滤→主料→≤3→可选求解→说明；写满短期菜列表 |
| REPLACE_ONE | 只换指定一道，排除当前三道 id |
| ADD_KIND | 只再追加 1 道该 kind；未明确说减少则不删已有菜；全列表菜号不重复 |
| MISSING | 追加缺少清单，去掉含该食材的菜，只补空槽 |
| SUBSTITUTE | 先病情适合检查；不通过保持原做法；通过只改说法不改克数 |

冲突：有待确认食材则本回合只确认；问候可前置再执行业务；职责外与业务并存时旁支一句后继续业务。

## 6. 增量执行

禁止在 `REPLACE_ONE` / `ADD_KIND` / `MISSING` 下对全部菜重跑 `RECOMMEND`。  
换一道、加汤、缺料补位均只改受影响槽位。  
**所有**写入短期记忆的菜列表必须按菜号去重；加菜未要求减少时不得删已有菜。

## 7. 食材归一分档

1. 精确 / 别名  
2. 高置信模糊 → 自动用 + 回显 + 写入短期映射  
3. 低置信 → `CONFIRM_FOODS`，必须确认后继续  
4. 未识别 → `unrecognized`，不当食材  

模型候选不得绕过食材编号表。

## 8. API

`POST /api/nutrition/agent/turns` 允许无 `foods`（问候/拒答/增量可仅 text + 会话）。

响应含：`sessionId`、`plan`、`dishes`（当前全集）、`needConfirm`、`memoryEcho`、`explanation`、既有工具痕迹字段（若有）。

## 9. 分期

- P0：会话短期记忆、理解→规划骨架、GREETING / OUT_OF_SCOPE / RECOMMEND、病情快照  
- P1：REPLACE_ONE / ADD_KIND / MISSING  
- P2：分档归一 + CONFIRM_FOODS  
- P3：SUBSTITUTE + 多任务同回合顺序执行打磨  

## 10. 验收

- 你好 → 身份介绍，不检索  
- 北京天气 → 拒答，不检索  
- 白蔡 → 高置信纠正回显后找菜  
- 土地（低置信）→ 只确认不给菜  
- 已有三道后换一道 → 另两道 id 不变  
- 加个汤 → 只多一道或先问替哪道  
- 糖尿病快照会话内不重复加载（同版本）
