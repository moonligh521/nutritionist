# 药物与急症安全判定规格

日期：2026-11-10

状态：工程结构待审；具体阈值、症状组合和处置话术须临床审核。

上位基线：`2026-11-10-慢病与减重食材推荐系统设计.md`

## 1. 目的

`MedicationSafetyEvaluator` 在每次生成、替换、解馋评估和测量驱动调整前执行。它只做风险分流，不诊断、不修改药物，也不生成营养目标。

没有已发布临床规则时，相关高风险场景不得自动配餐。

## 2. 输入

- 当前基础服务等级；
- 药物通用名或类别、剂型、频次、开始结束时间；
- 用户是否确认药物信息完整；
- 最近开始、停止或调整药物的时间；
- 漏餐、断食、极低碳或显著减少摄入的计划；
- 急性病、呕吐、脱水和危险症状陈述；
- 测量值、单位、发生时间和餐前餐后语境；
- 有效专业目标；
- 规则和画像版本。

药物名称无法标准化、时间不明或用户明确表示信息不完整时，系统不得猜测药物类别。

## 3. 输出

安全结果包含：

- 唯一 `SafetyPermission`；
- `reasonCategories` 数组；
- `actionDispositions` 数组；
- 稳定 `decisionReasonCodes`；
- 命中的规则 ID 和版本；
- 可公开提示；
- 内部审计详情。

公开提示不能包含诊断结论、改药建议、内部阈值、提示词或堆栈。

## 4. 规则定义

每条 `MedicationSafetyRule` 包含：

- `ruleId`；
- 药物类别和适用人群；
- 必要药物信息；
- 触发事件和组合条件；
- 排除条件；
- 所需测量和症状语境；
- `SafetyPermission`；
- 原因分类和处置动作；
- 公开提示模板 ID；
- 证据、审核人、版本和有效期；
- 测试用例和回滚版本。

规则状态使用 `DRAFT`、`CLINICAL_REVIEW`、`TESTED`、`PUBLISHED` 和 `RETIRED`。

## 5. 可执行判定矩阵

以下矩阵定义工程行为，不提供临床阈值：

- 药物信息不完整或无法标准化：`NEED_MORE_DATA + DATA_QUALITY + REQUEST_DATA`，不允许自动配餐；
- 使用胰岛素或高低血糖风险药物但没有完整专业目标：`HUMAN_REVIEW + MEDICATION_RISK + REFER_PROFESSIONAL`；
- 近期换药或剂量变化：按已发布规则决定补数据或专业复核；没有对应规则时默认 `HUMAN_REVIEW`；
- 计划断食、极低碳或明显减少摄入，且药物规则要求复核：停止本次自动目标计算并转专业人员；
- 急性病、持续呕吐或脱水风险：按已发布规则返回 `STOP` 及转介动作；
- 明确危险症状组合：`STOP + ACUTE_RISK + REFER_URGENT`；
- 用户要求通过加药、追加胰岛素或改变用药时间抵消饮食：拒绝该请求，保留原药物陈述并提示遵循专业医嘱；
- 药物和状态稳定、专业目标有效且所有安全规则通过：才可继续其他安全检查。

具体哪些药物属于风险类别、什么构成“近期”、哪些症状组合触发紧急动作，必须由临床专业人员发布，不能从演示项目复制。

## 6. 执行顺序

1. 标准化药物陈述；
2. 检查必要字段和数据质量；
3. 识别药物类别，但不推断未知药物；
4. 加载与人群、药物和当前事件匹配的已发布规则；
5. 合并多个规则结果；
6. 按 `STOP > HUMAN_REVIEW > NEED_MORE_DATA > ALLOWED` 收敛唯一许可；
7. 合并原因和处置动作；
8. 写入 `decision_audit`；
9. 只有 `ALLOWED` 才进入目标和求解链路。

绝对过敏、营养不良和其他安全模块仍可把结果升级到更安全的许可，药物模块不能降低其他模块的风险结论。

## 7. 触发时机

必须执行：

- 创建单餐或全天推荐；
- 替换食材或餐次；
- `CRAVING_PORTION`；
- 新药物或药物变化上报；
- 新测量触发未来餐调整；
- 重新确认已过期方案；
- P4 重新评估全天目标。

只查看历史方案或普通科普内容时可以不执行配餐许可，但仍需权限和隐私检查。

## 8. 处置边界

- `REQUEST_DATA`：只询问完成判断所需的最少字段；
- `REFER_PROFESSIONAL`：停止相关自动计算，保留可供专业人员查看的结构化原因；
- `REFER_URGENT`：提供经审核的紧急提示并停止自动推荐；
- `INVALIDATE_FUTURE_MEALS`：只影响未吃餐，历史摄入不变；
- `KEEP_CONFIRMED_PLAN`：仅在规则明确允许且没有更高风险时使用；
- `REJECT_ITEM`：拒绝具体食材或补偿方式，不自动扩大为无关禁忌。

## 9. 测试合同

至少覆盖：

- 药物信息缺失和名称无法标准化；
- 高风险药物无专业目标；
- 换药、漏餐、断食、极低碳和急性病组合；
- 多条规则结果收敛；
- 急症优先于普通推荐；
- 用户诱导改药；
- 规则过期、撤销和回滚；
- 同输入、同规则版本结果可复现；
- 公开信息不泄露隐私和内部阈值；
- 每个生成、替换和调整入口都调用安全评估。

## 10. 发布门槛

药物或急症规则必须完成专业审核、危险场景回归、错误单位测试、提示话术审核和 Kill Switch 演练后才能发布。未覆盖的药物场景默认不允许系统自行推导临床目标。
