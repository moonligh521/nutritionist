# 菜谱向量化与检索设计

日期：2026-11-16  
范围：营养服务菜谱推荐的 `nutrition_recipe` 写入与检索，以及 `platform-vector` 上支撑真实 Milvus / 百炼的必要改动。  
依据：`docs/方案` 第 4、5、11 节；验收按真实环境（`154.8.236.238:19530` + 百炼密钥）。

**读路径企业级补强（降级 / pool / 记忆贯通 / 空因）**：以 `2026-11-17-菜品推荐检索企业级闭环-design.md` 为准；本文侧重写入与集合字段。

## 1. 目标

保证已发布菜谱能按产品规则向量化写入，并能按字段过滤与（必要时）向量检索命中，再交给主料门槛选出最多 3 道做法。

非目标：全量对账运维台、下架删向量的完整后台、对话迁入 `platform-model`、个人小程序上线。

## 1.1 菜谱主键与菜名

- MySQL：`recipe.id`（`BIGINT AUTO_INCREMENT`）是唯一菜谱主键；已删除字符串业务菜号列。
- 子表 / `recipe_search_chunk`：`recipe_id BIGINT` = `recipe.id`。
- API / 目录 / Milvus：`id` 均为该数字的**字符串**（与食材 `CAST(food.id AS CHAR)` 一致）。
- Milvus 另存标量 `name` = `display_name`，Attu 可直接查看菜名。
- 标签字段为 `ARRAY<VarChar>`，过滤用 `array_contains` / `not array_contains`（当前 Milvus 不支持 `like "%x%"`）。

## 2. 数据流

```text
CSV 模版上传（菜号=已入库的 recipe.id）
  → 解析一行一道菜（菜名 / 种类 / 菜系 / 偏好 / 适合 / 不适合 / 向量文本）
  → 百炼 qwen3-vl-embedding 一次（1024 维）
  → MySQL recipe_search_chunk 存正文 + embedding_json
  → Milvus 集合 nutrition_recipe：已算向量 + 标量字段（禁止二次 embed）
  → 仅已发布菜进入推荐检索

检索
  → 拆出菜系、种类、偏好、模糊词；病情来自档案或请求
  → 点名或病情 → RecipeVectorFilter.expr（array_contains），必须带上
  → 仅有模糊词（如「清淡一点」）时才 embed 查询向量并 ANN
  → 返回数字字符串 id（约 30）→ 与目录交集 → 主料门槛 / 规则分 → ≤3 道做法
```

边界：

- `platform-vector`：embed / save / search / query；支持 `listFields`（ARRAY）与集合备注。
- 营养服务：字段怎么滤、主料门槛、克数、发布状态。
- 真库或密钥不可用：写入跳过、检索空；无点名且无病情时可退回全量已发布主料排序。

## 3. 写入

1. **一次向量化**：`RecipeVectorizer` 算出向量后写入 `VectorDocument.vector`；`MilvusVectorStore.save` 已有向量则不再调百炼。
2. **只写已发布**：未发布行可不落推荐检索；不写入 `nutrition_recipe`。
3. **种子数据**：`PublishedChunkSeeder` 不向 Milvus 写空的 kind/cuisine/tags；无标量来源时只补 MySQL 正文；完整标量以 CSV 上传为准。
4. **版本**：使用真实版本号覆盖同菜号字段与向量。
5. **集合字段**：`id`、`name`、`version`、`kind`、`cuisine`、`prefer_tags`/`suitable`/`unsuitable`（ARRAY）、`embedding(1024)`。首次写入自动建集；schema 变更时 drop 重建。

## 4. 检索

1. 从 `text` / 请求拆出菜系、种类、偏好与模糊词；病情来自档案或 `conditions`。
2. 有点名字段或病情 → `RecipeVectorFilter.expr` 必须进入检索；菜系不靠相似度混入。
3. **仅当有模糊词**时才做查询向量 ANN；只有点名/病情时走过滤结果（标量查询或等价路径），再做主料门槛。
4. 向量/Milvus 失败：无点名且无病情 → 全量已发布主料排序；有点名或病情 → **空候选**，不退回全库。
5. `HybridRecall.pool`：召回非空但与已发布无交集 → 空列表，禁止 fail-open。
6. 之后仍走主料门槛、规则分、最多 3 道做法。

## 5. 真库验收

| # | 步骤 | 期望 |
| --- | --- | --- |
| 1 | `consult.vector` → `154.8.236.238:19530` + 百炼 key | 能连、能 embed |
| 2 | 上传含川菜/非川菜、带适合字段的已发布样例 | MySQL + Milvus 有记录；只 embed 一次；Attu 可见 `name` |
| 3 | 检索「川菜」 | 只出川菜 id（数字字符串） |
| 4 | 检索带控糖等病情 | `array_contains(suitable, …)` 命中且非 unsuitable |
| 5 | 检索「清淡一点」 | 走向量；结果仍过主料门槛 |
| 6 | 无 key / 断 Milvus 且请求带点名过滤 | 不静默退回全库 |

## 6. 错误与降级

- embed 失败：可仍保存 MySQL 正文；不写 Milvus 向量行。
- Milvus 写入失败：记日志；不拖垮上传接口。
- 有过滤条件时检索失败：返回空，由上层说明没有符合的已发布菜。
- 无过滤条件时检索失败：退回全量已发布主料判断。

## 7. 测试

- 单测：`RecipeVectorFilter`、写入使用预计算向量不二次 embed、`HybridRecall.pool` 不 fail-open、点名/病情解析。
- 真库冒烟：按第 5 节手工或脚本跑通；密钥只放本地 `application-local.yml`，不入库。
