# 对话记忆分层设计

状态：施工中。与 `2026-11-17-对话规划与增量推荐-design.md` 配套。

## 1. 三层记忆

| 层 | 存什么 | 不存什么 | 生命周期 |
| --- | --- | --- | --- |
| **长期** | 结构化档案事实 | 聊天原文、当次口味口癖 | 跨会话，档案为准 |
| **短期（会话）** | 长期快照副本 + 本轮推荐过程态 | 未确认的猜测病情 | 会话 / sessionId |
| **工作记忆** | 本请求任务队列与中间结果 | — | 单次 HTTP |

## 2. 场景：什么进哪一层

### 2.1 长期（必须 / 建议）

| 事实 | 约束级别 | 来源 |
| --- | --- | --- |
| 病情编码（→ 控糖等过滤标签） | 硬 | ClinicalRecord |
| 已确认过敏原 | 硬 | ClinicalRecord |
| 已确认过敏原 | 硬 | ClinicalRecord |
| 口语饮食偏好（AVOID/LIKE，带时效） | 现行参与过滤/hints；详见时效偏好方案 | PreferenceStore |
| 用药名称 | 说明/安全引用 | ClinicalRecord |
| 测量是否禁止自动配餐 | 硬门禁 | ClinicalRecord |
| 稳定菜系/标签偏好 | 软；亦走时效事实 | PreferenceStore |

### 2.2 短期（会话）

| 事实 | 说明 |
| --- | --- |
| `longTerm` 快照 | 会话首次从长期装载，同 version 不重查 |
| 当前菜列表（去重） | 增量换菜/加菜 |
| 食材编号 foodIds | 本会话已识别 |
| 缺少清单 missing | 「没有可乐」 |
| 纠正映射 corrections | 白蔡→白菜 |
| 当次 textHints | 「今天清淡一点」未升长期前只在短期 |
| profile / revision | 求解与版本 |

### 2.3 不进长期

- 「你好」等寒暄  
- 「北京天气」  
- 未确认的错别字猜测  
- 模型说明草稿  
- 从闲聊推断的病情  

## 3. 装载规则

```text
有 patientId
  → version = patient:{id}
  → 若会话无该 version 快照：读 ClinicalRecord + TasteProfile → LongTermMemory
  → 写入 SessionMemory.longTerm
无 patientId 但请求带 conditions/prefer/avoid
  → version = request
  → 仅用请求构造快照（不写档案）
```

用户本轮明确「以后都吃川菜 / 不吃香菜」且带 patientId 时，可写入口味档案（长期），并刷新快照。  
「这顿清淡」只进短期 hints，不写长期。

## 4. 执行时用法

- `measurementStopsPlanning` → 拒绝 RECOMMEND / 增量找菜，只允许问候说明  
- `allergens`（硬）+ 现行 `AVOID`（偏好）→ 过滤；过期偏好不参与  
- `conditions` → 适合/不适合硬过滤，优先于 LIKE  
- 现行 LIKE / 菜系 / 标签 → hints；「这顿清淡」仅短期  
- 偏好时效与以前/现在问答见 `2026-11-17-时效饮食偏好完整方案-design.md`  

## 5. 响应回显

`DialogueReply` 带回 `longTerm` 摘要，便于客户端展示「本会话已带上：控糖、忌口香菜、偏好川菜」。
